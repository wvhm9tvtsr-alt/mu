# 手機與電腦同步：一次性設定

程式與資料表腳本已備妥。**尚未設定 Project URL／Publishable key 並執行 SQL 時，不會對外傳送記帳資料，也沒有啟用跨裝置同步。**

1. 使用本人帳號登入 <https://supabase.com/dashboard>。若尚無組織，按 New organization、選 Free，再建立 New project。資料庫密碼由本人設定並保存，不要傳到聊天或 GitHub。
2. 等專案建立完成，開 SQL Editor → New query。將 [setup.sql](setup.sql) 完整貼上、按 Run。網站同步區亦提供「複製專案初始化內容」。腳本可重跑，不刪除既有紀錄。
3. Authentication → URL Configuration：Site URL 設為 `https://wvhm9tvtsr-alt.github.io/mu/`，Redirect URLs 加入相同網址。Email provider 開啟，供記帳帳號註冊與登入。
4. 從專案 Connect／Settings → API Keys 取得 Project URL 及 **Publishable key**（或舊版 anon key）。不可使用 Secret、service_role 或資料庫密碼。網站最上方「手機／電腦同步」→「專案連線設定」填入這兩個公開值。
5. 第一次在記帳網站按「首次建立帳號」，用能收信的信箱建立自己的記帳登入帳號，依信件確認後登入。這不是 Supabase 後台管理帳號的登入動作，不需要 GitHub 密碼。
6. 先在**有完整紀錄的裝置**登入，選「將這台資料存到雲端」。另一台設定同一專案、登入同一記帳帳號後，選「使用雲端資料」。如果兩台已各有不同紀錄，先分別下載完整備份，再核對來源。

公開連線設定亦可由維護者寫入根目錄 `sync-config.js`，並將同一份檔案內容同步替換 `index.html` 內的設定 script，發布後手機與電腦就不需要各填一次。只有 URL 和 Publishable／anon key 可以提交；帳密與 Session token 只能留在本人裝置。

## 同步行為

- 包含所有分頁資料：股東、代理、薪資、叫貨、猛健樂、兩種庫存、成本與回本試算、醫師結帳、營運分析／活動／回訪及工作表。
- 儲存後約 1.2 秒嘗試上傳，開啟頁面時約每 15 秒檢查更新；恢復連線或切回頁面也會檢查。網路中斷時仍可記帳，只保存於本機，恢復後再核對同步。
- 尚未儲存的輸入不會被雲端覆蓋。不同分頁的更新依上次共同版本合併；同一分頁在兩台同時修改時，請使用者選擇保留哪一份，不嘗試猜測金額或合併庫存出入帳。
- 替換前在 IndexedDB 留下最近 5 份完整快照；可下載最近一份，也能先下載本機完整備份。一般匯出檔不包含登入憑證。多個頁籤使用同一瀏覽器時，過期頁籤不可覆蓋另一頁籤的儲存，請重新整理後繼續。
- 同步包上限 8 MB。瀏覽器儲存空間不足時不會標記同步成功；套用失敗會回復本機，另保留同步前備份。
- 登出不會刪除本機資料。首次綁定後，不會把這台資料自動上傳到另一個登入帳號。

## 權限與版本

`mu_sync_documents` 以 `auth.uid()` 作為使用者主鍵。RLS 只允許登入者讀取自己的列，匿名不能讀取。登入者亦不能直接新增、更新或刪除資料表；只能呼叫 `mu_save_document`，由函式以目前登入者身份執行原子版本比對。版本衝突回應 `40001`，避免較舊裝置無聲覆蓋較新資料。

初始化腳本不會建立測試使用者或放入任何實際客戶紀錄。測試使用 PostgreSQL 相容的 PGlite 驗證權限與 CAS，再用兩個獨立瀏覽器及模擬 Supabase API 驗證同步、離線、衝突、備份、帳號隔離及儲存不足。真正專案連線仍需上述本人設定及最後實際登入驗證。
